## 一、插件功能

安装并启用后，Harness 左侧会出现「用量中心」。插件只统计供应商实际返回的 Token，不做字符数或上下文大小的推算。

### 1. 用量与质量

1. 总 Token、未缓存输入、输出、缓存读取、缓存写入、推理 Token（供应商报告时才显示）。
2. 缓存命中率，以及「有缓存命中的请求占比」（两个口径分开统计，不混用）。
3. 调用次数、重试次数，以及有可靠终止标记时的失败/取消。
4. 精确 LLM 时长、TTFT、解码速度及 P50/P95（只在原始边界完整时汇总）。
5. 每个字段的覆盖率，缺失就是「未知」，绝不补 0。
6. 历史冷会话回填、fork 继承前缀去重。

### 2. 花费与预算（1.1.0 新增）

1. **花费估算**：按价格表对四个桶分别计价，KPI、趋势图、模型对比、明细表、CSV/JSON 都带 `¥` 金额。
2. **预算卡**：配置日/月预算后显示进度条（80% 变黄、100% 变红）。
3. **月底预测**：按近 7 日均值推算本月剩余天数的花费。
4. 价格与预算都在 `cordis.patch.yml` 配置（见第四节），花费始终标注为「估算」，不是供应商账单。

### 3. 图表（1.1.0 重做）

1. **悬停**任意日期即出现明细：当日数值、占比、与前一日环比、覆盖率；Tab 聚焦后可用 ←/→ 逐日切换。
2. **图例开关**：点击图例可隐藏/显示该序列（会被记住）。
3. **拖拽缩放**：在趋势图上拖出区间即把筛选收窄到那几天，双击还原；**点击某天**也可下钻。
4. **累计 / 对比上期**：右上角两个开关，累计曲线；「对比上期」叠加显示上一个等长周期的虚线，并在 tooltip 给出上期数值与差距。
5. **Token ⇄ 花费**切换；模型对比可在 Token 与花费之间切换，点击某个模型即把它设为筛选条件。
6. **动画**：折线绘制、面积渐显、柱状生长、点位放大、数字滚动、悬浮卡片淡入；系统开启「减少动态效果」时自动关闭。
7. **周×小时热力图**：一眼看出哪天的哪个时段最费。
8. 缓存环图分「读 / 写 / 未缓存」三段。

### 4. 明细、导出与快捷键

1. **明细表**：服务端分页（不再只显示前 500 行）、点列头排序、关键词搜索、列显示设置、点会话 ID 直接筛到该会话、复制 `call_key`。
2. **导出**：CSV / JSON（含 `cost_rmb`、`cost_complete`）、当前图表 PNG、Markdown 摘要复制。
3. **链接**：当前筛选、区间与视图开关会同步在地址栏，「链接」按钮可一次复制分享。
4. **快捷键**：`1/2/3/0` 切 7/30/90/全部，`R` 刷新，`E` 导出 CSV，`P` 导出 PNG，`/` 聚焦搜索。
5. **无障碍**：图表带隐藏数据表与 `aria-describedby`，表格有 `caption`/`scope`。

> 供应商没有返回 Token 数据的调用不会入库，也不会影响其他调用。

## 二、安装方法

### 方法 A：Harness Desktop（推荐）

1. 打开 Harness。
2. 进入「插件」页面。
3. 选择「添加插件」或「安装插件」。
4. 选择本压缩包中的 `local-dsh-usage-center-1.1.0.tgz`。
5. 安装完成后启用插件。
6. 在顶部「应用」菜单点击「重启应用与 Host」，让前端页面和统计后端都加载新版本。

> Desktop 的 `desktop profile` 由 Harness 自己管理，建议直接在插件页导入 TGZ，不要用命令行强行管理它。

### 方法 B：命令行安装（Web 或自管 profile）

```powershell
dsh plugin --profile <profile名称> add "D:\插件路径\local-dsh-usage-center-1.1.0.tgz"
```

本地开发也可以直接链接源码目录，改完刷新面板即可（后端改动仍需重启）：

```powershell
dsh plugin --profile <profile名称> add "link:D:\plugins\deepseek-harness-usage-center"
```

## 三、升级方法

1. 在原来同一个 profile 里直接安装新 TGZ，让新版覆盖旧版。
2. 完成后「应用 → 重启应用与 Host」。仅刷新页面只刷新界面，不一定重新加载统计后端。
3. 不要为了升级删除数据库或清空 profile；保持同一 profile 与数据目录，历史才能接续。

## 四、配置花费价格与预算（可选）

在 profile 的 `cordis.patch.yml` 追加（或修改）下面这段，改完重启：

```yaml
- id: usage-center
  name: "@local/dsh-usage-center"
  config:
    pricing:
      deepseek-flash: { inputPerM: 2, outputPerM: 8, cacheReadPerM: 0.04, cacheWritePerM: 0 }
      deepseek/deepseek-v4-pro: { inputPerM: 9, outputPerM: 27, cacheReadPerM: 0.3, cacheWritePerM: 0 }
    budget:
      daily: 30
      monthly: 600
```

要点：

1. 价格单位是「元 / 百万 token」，四个桶必须齐全；缺字段或负数会在启动时报错，不会静默按 0 计价。
2. 匹配顺序：`provider/model` → `model` → `provider/*` → `*` → 内置表。
3. 内置价目与 `@local/dsh-runaway-watchdog` 一致（DeepSeek 高峰档），不配置也能看到花费。
4. `budget` 省略或为 0 时不显示预算卡。

## 五、日常使用

1. 启用后无需额外操作，正常使用 Harness 即可。
2. 首次启用会在后台回填历史会话，回填期间数字会继续变化。
3. 面板每 15 秒刷新一次；切到后台标签页时暂停，回到前台立即更新，数据没变时后端返回 `304`，不会重复拉全量。
4. 顶部会显示「更新于 / 数据截止」；超过 1 分钟未更新会给出「数据可能过期」提示。

## 六、重要提示：建议不要随意卸载

为保持统计连续、避免新旧数据对不上，建议安装后长期启用，不要频繁卸载、重装、切换 profile，或移动/删除数据目录。

1. 插件停用期间无法记录实时精确时延、TTFT，以及标题生成、会话压缩等只靠实时捕获的调用。
2. 普通会话 Token 在日志仍存在时通常可回填；已删除的会话日志无法恢复。
3. 换到另一个 profile 会看起来像「历史数据消失」，实际是读了另一套数据库。
4. 删除或移动数据库后，旧统计可能无法继续匹配去重。

临时关闭插件不会自动清空已入库数据；切回同一 profile 且数据目录仍在时，可以继续读取原库并补回可核验的历史 Token。但「通常保留」不等于已备份。

## 七、数据保存位置

```text
<profile>\usage-center\usage-center.sqlite
```

不要手动修改、移动或删除该文件及同目录下的 SQLite 辅助文件。

重装 Harness、迁移电脑或更换 profile 前建议：

1. 导出 CSV 或 JSON 留档。
2. 完全关闭 Harness。
3. 备份整个 `<profile>\usage-center\` 文件夹（不要只复制单个 `.sqlite`）。
4. 同时保留原来的 Harness 会话日志。

## 八、常见问题

**安装后看不到「用量中心」**
确认插件已启用，然后「应用 → 重启应用与 Host」。

**花费和账单对不上**
插件按你配置的价格表估算，不是供应商账单；DeepSeek 有高峰/低谷价，内置表取高峰价（宁可高估）。可在 `pricing` 里改成你的实际价。

**「对比上期」按钮是灰的**
该功能需要明确的时间范围；选「全部」时没有可比的上一周期，改用 7/30/90 天或自定义日期即可。

**为什么有的数字带「部分覆盖」**
供应商只报告了部分字段（例如没有缓存读写），插件把这些未知如实标出，不补 0；覆盖率在图表角标和「数据覆盖」卡里都能看到。

**某个供应商没有统计数据**
该供应商可能没有返回可用 Token，插件跳过而不是估算。

**历史 Token 有数据，但历史时延是空白**
正常现象：旧日志能恢复 Token，但没有完整的实时起止边界。

**必须卸载怎么办**
先导出 CSV/JSON，完全关闭 Harness，备份整个 `usage-center` 文件夹，再卸载。
