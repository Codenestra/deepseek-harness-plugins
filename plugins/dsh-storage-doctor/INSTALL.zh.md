# 存储医生（dsh-storage-doctor）安装使用说明

版本：**0.1.0** · 维护者：Codenestra

磁盘占用扫描、增长趋势、清理预览、回收站与还原。

## 安装与启用

1. 从本仓库的 [Releases](https://github.com/Codenestra/deepseek-harness-plugins/releases/tag/v0.1.0) 下载对应插件的 ZIP 并解压，或直接下载 `.tgz`。
2. 使用 DSH 的插件管理安装本地 `.tgz` bundle；若界面未提供本地文件入口，可让 DSH 对话中的代理通过 `plugin_manager` 的 `install_bundle` 安装，传入已下载的 `.tgz` 绝对路径。不要把 ZIP 当作插件安装包。
3. 包内带有 `cordis.patch.yml`，由插件管理器注册 host 和客户端入口。在插件页确认启用。
4. 如果宿主提示需要重启，等全部运行任务自然结束后，执行「重启应用与 Host」。然后检查对应侧栏入口。

**环境**：本版本在 Windows 桌面 DSH `0.1.7-rc.2` 本地构建上完成功能验收；Node.js 要求 `>=22.19.0`，Cordis peer 为 `~4.0.4`。其他 DSH 版本尚未做兼容性验收。

## 日常使用（四个页签）

- **总览**：点「立即扫描」得到总量、分类占比（会话/附件/插件数据/运行时/模型/日志/缓存…）、大文件 Top 10（单文件 ≥ 50 MB）、插件数据体积榜。扫描只读、可中断、同一时间只跑一个。
- **趋势**：每次扫描落一个数据点的 SVG 增长曲线（总量 + 会话日志 + 插件数据），悬停查看时间与体积；自动扫描默认每 24 小时一次（页脚与趋势页显示当前配置）。
- **清理预览**：设三个保留参数（会话保留天数 / 日志保留天数 / 临时文件时龄），可选勾选「ASR 模型」（默认不勾；清理后下次使用语音转文字会重新下载约 230 MB 模型）→「生成预览」→ 候选逐项列出（路径/类别/体积/最后活动/会话标题），受保护项灰显并标注原因 → 勾选后「移入回收站」，第一次点击变橙色确认、第二次才执行。
- **回收站**：批次列表（时间/策略/项数/体积/状态）→「还原」整批原路返回（原路径被占用时整批拒绝、绝不覆盖）；「彻底删除」需精确输入 `PURGE` 二次确认，是唯一不可逆操作。超过保留期（默认 7 天）的批次会被自动清空——只动本插件回收站。

## 配置（YAML + 重启）

**部署限制**：当前宿主不为第三方插件渲染原生配置表单（插件页「配置」按钮需要插件自带客户端配置页，本插件按验收口径未提供），因此**所有配置都通过 YAML 修改**：

编辑 `~/.dsh/profiles/desktop/cordis.patch.yml`（Windows 即 `C:\Users\<你>\.dsh\profiles\desktop\cordis.patch.yml`），追加或修改：

```yaml
- id: storage-doctor
  disabled: false
  config:
    autoScanIntervalHours: 24   # 周期扫描间隔（小时）；0 = 关闭
    trashRetentionDays: 7       # 回收站自动清空保留期（天）；0 = 不自动清空
    attachmentGc: false         # 实验性附件 GC 总开关（见下节）
    # attachmentGcDays: 30      # 可选：无引用对象时龄门槛（天，1–3650）
    # topFileThreshold: 52428800  # 可选：大文件榜阈值（字节）
    # home: 绝对路径             # 可选（调试）：指向另一个 DSH home
    # databasePath: 绝对路径     # 可选：sqlite 台账位置
```

改完后必须通过应用菜单「**重启应用与 Host**」生效（配置在插件激活时读取）。

## 附件 GC（实验性功能，默认关闭）

针对内容寻址图片对象库 `attachments/v1/objects` 的无引用回收。**默认关闭**；关闭时清理页底部的「附件 GC（实验性）」卡片仍可提供**只读干跑报告**（对象数/体积、引用语料统计、完整性与失败明细），但不会给出任何清理按钮。

**启用与使用**：

1. YAML 中设 `attachmentGc: true` → 重启应用与 Host。
2. 清理页 → 附件 GC 卡片 → 设「无引用超期天数」（默认 30）→ 点「干跑报告」：确认 `语料完整`；任何解析失败/结构异常都会 fail-closed（零候选并拒绝清理，「解析不了」≠「无引用」）。
3. 点「生成 GC 预览」→ 勾选对象（**建议首次演练只勾自建测试文件**）→「移入回收站」两段确认 → 回收站页可一键还原。
4. 用完建议改回 `attachmentGc: false` + 重启。

**安全边界**：GC 清理仅手动触发、干跑先行；清理前重建引用语料并逐项复核（引用复现的对象自动跳过并给出原因）；带图片扩展名的异形对象（如 `<sha>.png`）只盘点保护、永不清理；`file-objects`/`files` 与其他插件的衍生缓存不在范围内；移动全部走回收站，可还原。

## 卸载

1. 插件页 → 存储医生 → 关闭开关（停用）或执行卸载/移除 bundle。
2. 卸载前请确认回收站中没有还需还原的批次。
3. 可选清理残留：`<DSH_HOME>/.storage-doctor/trash/` 回收站和 `<profile>/storage-doctor/` 台账目录（使用自定义路径时以实际配置为准），确认不需要后手动删除；并可从 `cordis.patch.yml` 移除 `storage-doctor` 条目。
